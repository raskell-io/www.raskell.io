The longer I think about agents and workflows, the less they look like rivals. An agent is how you find a path through terrain nobody has mapped. A deterministic procedure is how you keep that path once you know it will be walked again. Intelligence explores; determinism is the residue it leaves behind, the part worth not thinking about any more. Organisations have always worked this way with people, turning what capable employees improvised into routines wherever the work repeated, and [The River and the Canal](/articles/the-river-and-the-canal/) argues that agents simply make the exploring half cheap.

That moves the interesting decision. It is not whether to use an agent or a workflow for a process, but when a path has been found often enough, with stakes high enough, that it should stop being rediscovered every time. It is the same question as the one in [The job is choosing when to be deterministic](/notes/the-job-is-choosing-when-to-be-deterministic/), asked one level up: there it was which part of a context should move from model calls into code; here it is which part of a company's work should move from agents into procedures. I expect to keep asking it at every scale I work on.

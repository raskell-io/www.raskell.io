When making something costs almost nothing, the economics of keeping it change. A general-purpose machine that does many jobs badly is worth maintaining only while building a better one for each job is expensive. Once building is cheap, the sensible design keeps one thing permanent, the factory, and makes everything else purpose-built: made for a mission, used, and taken apart. I took the image from a piece of internet fiction about a factory under the sea, as I described in [The River and the Canal](/articles/the-river-and-the-canal/), but the logic holds without the aliens. Software has worked like this for decades, because copying a binary is free, and agents now extend it to the things software used to need people for: a workflow written for one kind of case, a tool built for one migration, a report generator built for one audit.

The habit this asks for is retirement by default. Purpose-built things should come with an end, the way [the agent factory](/notes/the-agent-factory/) runs each agent in a microVM that lives for one task. What accumulates in a company that cannot retire anything is not capability but maintenance. The same pattern repeats at every scale I look at, from a factory method in code to a factory of factories, which is usually a sign that it is real.
